# Спецификация: сайт конспектов, полностью с нуля

Заказчик — Артём, 2 курс юрфака ВШЭ («Юриспруденция: цифровой юрист»). Сайт ставится как Android-приложение (Chrome-обёртка), поэтому главное — телефон (390px), но и десктоп должен выглядеть хорошо. Он просил: минимализм, ничего лишнего, никаких функций сверх перечисленных.

## Файлы
- `data.json` — все данные (см. схему). Не редактировать.
- `marked.min.js` — markdown-парсер (глобал `marked`, `marked.parse(md)`).
- `build.py` — сборка: в шаблоне ставишь `<!--DATA-->` и `<!--MARKED-->`, запускаешь `python3 build.py template.html out.html`. Данные никогда не вписывать руками — только через сборку. Итог — один самодостаточный html.

## Схема data.json
```
{ "subjects":[ { "id":"civil", "name":"Гражданское право", "hue":70,
                 "about": "markdown или null",
                 "notes":[ {"id":"civil-1","title":"…","short":"…","date":"1 сен","md":"markdown"} ] } ],
  "schedule":[ {"d":"2026-10-12","b":"11:10","e":"12:30","n":"Уголовное право (Общая часть)","k":"Семинар|Лекция",
                "r":"430","s":"crim|null","t":"ФИО препода","m":"email","q":"должность","bd":"адрес корпуса","g":"…","u":"…"} ],
  "tickets":{ "const":[[n,"вопрос","ответ markdown"],…], "crim":[…], "civil":[…] } }
```
Предметы без notes (notes:[]) есть в списке ради «О предметах» — на главной их не показывать, но в «О предметах» показывать всех, у кого about не пустой.
Расписание: в data.json зашито на 26 недель; плюс на сайте рядом лежит `schedule.json` (тот же формат массива) — при загрузке попробовать `fetch('schedule.json',{cache:'no-store'})`, если получилось — использовать его, если нет — встроенное.

## Что должно быть (ровно это)
1. **Главная «Конспекты»**: «Ближайшие пары» (3–4 ближайшие по расписанию, с датой/временем/аудиторией; «сегодня»/«завтра»), список предметов (только с конспектами) и внутри — конспекты по датам. Кнопка/ссылка «Продолжить» на последний открытый конспект (localStorage, в try/catch).
2. **Страница конспекта**: заголовок, предмет, дата, markdown через marked; переключение между конспектами предмета (вкладки или список); назад/дальше. Таблицы в конспектах должны скроллиться по горизонтали на телефоне.
3. **Расписание**: по неделям (← текущая неделя →), дни, пары; по нажатию на пару раскрывается препод, должность, email, адрес корпуса.
4. **Билеты**: три вкладки — Конституционное (const, 113), Уголовное (crim, 46), Гражданское (civil, 133). Список вопросов с номерами; ответ скрыт и раскрывается по нажатию (details/summary), рендерится как markdown. Подпись «вопросы прошлых лет». У гражданского вопросы с n ≤ 86 — «1–2 модуль», остальные — «3–4 модуль» (разделить подзаголовком), плюс строка «Сборника ответов не было, ответы составлены по ГК РФ». Всё компактно.
5. **О предметах**: для каждого предмета с about — раскрывающийся блок с markdown (там таблицы с формулами).
6. **Поиск** по всем конспектам (и по билетам): поле ввода, результаты со сниппетом и подсветкой.
7. **Размер шрифта** текста (3 ступени, запоминать в localStorage) и светлая/тёмная тема (prefers-color-scheme + ручной переключатель).
8. Навигация между четырьмя разделами: Конспекты · Расписание · Билеты · О предметах. Роутинг по hash (#civil-1, #schedule, #tickets-crim, #about), кнопка «назад» браузера должна работать.
9. `<head>`: `<meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover">`, `<meta name="theme-color">`, `<link rel="manifest" href="manifest.webmanifest">`, `<link rel="icon" href="icon-192.png">`, `<title>Конспекты</title>`. Учитывать env(safe-area-inset-*).
Больше ничего не добавлять (ни закладок, ни статистики, ни анимаций ради анимаций).

## Технические правила
- Один html-файл, весь CSS и JS внутри, без фреймворков. Шрифты только с fonts.googleapis.com. Никаких внешних скриптов, кроме встроенного marked.
- Цвета — через переменные на `:root`, тёмная тема: `@media (prefers-color-scheme: dark){:root:not([data-theme="light"]){…}}` и `:root[data-theme="dark"]{…}`. У body явный background.
- Телефон: боковые поля 16px, никакого горизонтального скролла страницы, кнопки ≥ 40px. Длинные слова/таблицы не должны ломать макет.
- Весь текст на русском. Экранировать html в данных (esc()).
- Проверить в headless Chromium (playwright уже установлен: `python3 -c "from playwright.sync_api import sync_playwright"`): открыть file://…/out.html с #, #civil-1, #schedule, #tickets-civil, #about на 390×844 и 1280×900, убедиться что нет pageerror, сделать скриншоты, посмотреть их (Read png) и поправить, что криво. Проверить, что `document.documentElement.scrollWidth <= window.innerWidth` на телефоне на каждой странице.
